three modes

One tool. Three ways to drive it.

prompt mode — user › or you ›

Ask for what you want. Read what it plans.

The default. Type intent in plain English and Shellia comes back with a structured plan: one step per command, each tagged with its risk grade. Approve, edit (e), or bail (n) per step.

  • Multi-step plansIterates after each command if a later step depends on what the previous one returned.
  • Session memory"do the Docker thing from before" actually works.
  • InspectableUse --verbose to see the full plan, classification, and capture limits.

how it works

Not a black box.
A live shell with a model in the loop.

Four phases run per request. At each phase, the next action is visible before it runs.

01 / read

Local context

Shellia detects cwd, current user, OS, and shell engine, plus a small in-process memory of what just happened. Repository facts are inspected through explicit commands when needed.

02 / plan

Propose

Your instruction + that context goes to the configured LLM. It comes back with a structured, multi-step plan — not a wall of prose.

03 / classify

Re-grade locally

Every command is re-classified safe, risky, or dangerous by rules that live on your machine — not whatever the model felt like saying.

04 / confirm

Execute & observe

You see the plan. You confirm or edit. Shellia runs it, captures output, and if a later step needs that output, it re-plans before continuing.

safety model

Shellia doesn't trust the model. Neither should you.

Every command — proposed or pasted — is re-classified by a local rule set before it's allowed near your shell. The model's opinion doesn't get a vote.

safe

Read-only and obviously harmless

Listings, status, inspections. Can auto-run under --yes-safe.

risky

Mutates state in ways you'd want to notice

Filesystem changes, network pulls, container ops. Always confirmed.

danger

Could ruin your week

sudo, destructive deletes, system modifications. Confirmed loudly. No defaults.

live · local classifier
safe · auto-runnable risky · prompts dangerous · confirms loudly
runtime

Configure once. Stay weird.

One config file, named model profiles, four visual themes, sensible defaults. shellia config init creates ~/.config/shellia/config.toml; the old ~/.shellia/config.toml path is only a fallback. default_model picks the LLM profile. shell_mode picks how /shell runs. ui.style picks how the conversation is structured.

  • [[models]]name each endpoint and select it with default_model or --model-name
  • supports_response_formatleave enabled for OpenAI/llama.cpp · disable for MLX LM Server
  • shell_mode"interactive" drops into a real TTY · "plain" stays structured
  • command_modesame toggle for !<cmd>
  • ui.styleplain · guide · bands · cards; switch live with /theme
  • prompt_identityuser shows the terminal username · you keeps the prompt generic
  • confirmation_defaultnone · yes · no · edit · interactive
  • --yes-safeauto-runs commands the local classifier already marked safe
  • continue_on_errorafter a failure, skips dependent steps and runs only explicitly independent ones
  • capture_*_bytesbounded log capture so the model never sees a 4MB log

quick start

Start simple.
Stay explicit.

The whole thing in 6 lines.

Default to prompt mode for anything multi-step. Drop to ! when you already know. Use /shell when you want a manual loop that still feeds the model. Every option appears in --help — but you rarely need it.

  • y — run the proposed command as-is
  • e — edit before running
  • i — run interactively in a real TTY
  • n — bail out

No keystroke maps to "do it anyway, I trust you". That's a feature.

# grab the binary
$ tar -xzf shellia_darwin_arm64.tar.gz
$ mv shellia /usr/local/bin/

# run it
